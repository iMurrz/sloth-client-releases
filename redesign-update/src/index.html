REVIEW YOUR SESSION FILES

Session Seal hashes enabled top-level mod JARs and files under scripts/ and kubejs/. It does not upload files or read accounts. First approval records what is present; review its origin yourself. A matching hash does not establish that a mod is safe.

Inspect and approve with Minecraft closed. Intentional updates can change your seal. Each approval rechecks the files and binds the seal to this instance using a locally protected key. Copied seals do not grant approval. Review expires after ten minutes.

WHAT THE BOUNDARIES MEAN

Account credentials stay in the main process, encrypted for this OS user when secure storage is available. They are not sent to the interface. The Minecraft session token is delivered through a pipe rather than the process command line. Signed updates and isolated interface windows provide separate protections. When secure storage is unavailable, seal approvals also need review after restarting Sloth.

Minecraft mods execute with your user account's access. Session Seal detects changes in the listed folders; it does not sandbox mods, attest their safety, or protect against malware already running as you. Java, libraries, launcher files, configuration and other folders are outside its seal scope. Secrets and private server logic must stay on a server you control, never inside a distributed client.
